## 原有能力的核实与复用

四个基座、12 个情境、六个可选工具、原则编辑确认、Profile 修订、回答材料及原则快照、本机保存/刷新恢复/导出均在 HEAD 中实际存在，直接复用。无导入 JSON 备份的界面，所谓恢复是本机已有数据的读取及损坏时保护/导出，未把不存在的导入功能算作已完成。

旧问卷把选项对应到基座，没有情绪分离；首屏把 12 题放在主要路径。输入的问题只留在输入框，选定后还要再发送。原 `applyBase` 会清空当前消息，后续对话已有原则版本及材料快照机制。

## 本轮完成

默认入口改为一句困扰、生活情境和“不知道怎么说”。最多三步分别记录处境/反应、求助方向、愿意试试的依据；第二步已有明确求助方向可提前比较，随时可以不答题先聊。12 题保留为可选深入探索，复用原框架和情境，选项改为明确探索意愿并加入疲惫、不服/嫉妒、矛盾/说不清；这些反应和自由补充不计分，旧选项 ID 不重新解释。

推荐使用透明编辑规则，引用真实点击的文本。默认两候选，多种明确依据时最多三候选；解释内核、推荐性质、同题应用预览、前提与边界。没有明确信息时只给标明“非匹配”的体验入口。自由输入不做情绪/人格分类，也不暗写个人原则。两个常见情境有定向产品应用预览，其余使用明确标示的一般思考方式；预览不是实时 AI。

点击试用后才保存基座，并自动发送原问题、反应、求助和补充。不选基座时，经同一服务端接口生成明确标示的探索回应，来源为空、原则提议被服务端清除。模型、API 地址、reasoning、计费配置、鉴权和 secrets 均沿用原配置。长的深入探索上下文与原问题合并时不再截断到 6000 字；单条请求上限与已有恢复上限对齐为 12000 字，累计字节限制仍保留。

切换基座保留当前消息及旧快照；下一条使用当前确认的基座和原则。原则候选仅在用户明确要求形成/修改时提出。提示明确要求先回答、最多一个必要问题，拒绝反问时不再追加问题，区分原思想、产品转译、现实推导和事实不确定性。

轻量问答与可选问卷的继续动作均先检查明确危机表达；当前危险直接分流，不经过普通匹配。普通消极表达不单独触发危机。上游连接中断单独提示，保留输入供重试。

[四基座内容评议](evidence/first-experience/AI-REVIEW.md)逐项区分哲学理由、现实推导和共同建议。完整浏览器链路另有两条真实回答。来源白名单校验不等于每句话有学术保证。

## 未验证、限制与暂缓

- 上游限流和偶发连接中断真实存在；本轮保持手动重试，不改模型、套餐或增加付费重试策略。
- 四基座的具体行动建议有复盘/索取反馈的趋同，哲学理由有区别，尚无长期忠实度评估。常见情境以外的候选预览仍是一般方法，具体化发生在选定后的真实回答。
- 没有验证实体手机、Safari、屏幕阅读器和生产部署；本轮不发布，因此线上仍是原版本。
- 未声称开放文本分类、人格测量、危机识别完备、跨设备同步或备份导入。未完成问答草稿沿用页面内存策略，刷新会重开；成功回答开启本机保存后可恢复，登录跳转保留待发送内容。
- 既有样式检查报出 3 个旧 CSS 提示（侧边线和宽度过渡），没有扩展成本轮整站设计重做；浏览器翻译扩展造成一次属性水合警告，不是应用内容丢失。
- 保留既有署名、固定版本、许可及修改说明；未扩充基座、价值卡、商业化或架构。
